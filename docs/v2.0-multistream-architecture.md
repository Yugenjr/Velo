# Velo V2.0: Multi-Stream Realtime Runtime Architecture

## 1. Executive Overview

Velo V2.0 extends Velo from a single-stream realtime multimodal AI runtime into a **multi-stream runtime** capable of concurrently ingesting, decoding, scheduling, fusing, and inferring across $N$ independent media sessions.

The primary architectural challenge in multi-stream realtime AI is balancing **isolated state** (stream-level decode contexts, queues, pacing, and fault domains) against **shared resources** (GPU VRAM, CUDA execution streams, VLM model weights, and compute capacity).

```
                      +-------------------------------------------------------+
                      |                 MultiStreamRuntime                    |
                      |  - Session Registry: dict[stream_id, StreamSession]   |
                      |  - Global GPU Budget Coordinator                      |
                      |  - Multi-Stream Fair Inference Dispatcher             |
                      |  - Global & Per-Stream RuntimeMetrics (Hierarchical)  |
                      +-------------------------------------------------------+
                                    |                           |
                +-------------------+                           +-------------------+
                |                                                                   |
+-------------------------------+                                   +-------------------------------+
|     StreamSession ("cam-01")  |                                   |     StreamSession ("cam-02")  |
| - Stream / RtpReceiver (NVDEC)|                                   | - Stream / RtpReceiver (NVDEC)|
| - AIScheduler (Adaptive FPS)  |                                   | - AIScheduler (Adaptive FPS)  |
| - AudioScheduler + RingBuffer |                                   | - AudioScheduler + RingBuffer |
| - TemporalFusion (Sync Engine)|                                   | - TemporalFusion (Sync Engine)|
| - Ingestion / Pacing Workers  |                                   | - Ingestion / Pacing Workers  |
| - Stream Metrics Collector    |                                   | - Stream Metrics Collector    |
| - Fault Domain Isolation      |                                   | - Fault Domain Isolation      |
+-------------------------------+                                   +-------------------------------+
                \                                                                   /
                 \                                                                 /
                  +---------------------------------------------------------------+
                  |                   Shared Resources & Hardware                 |
                  |  - Shared VLM / ASR Model Instance (Weights in GPU VRAM)      |
                  |  - Shared CUDA Context & GPU Allocation Pool                  |
                  |  - Asynchronous Generator Event Stream                        |
                  +---------------------------------------------------------------+
```

## 2. Resource Audit & Isolation Matrix

| Resource Domain | Scope | Allocation Strategy | Rationale & Failure Boundary |
| :--- | :--- | :--- | :--- |
| **NVDEC Decoder** | Stream-Local | One `NvDecoder` context per stream | H.264 bitstream parsing (SPS/PPS) is stateful. Independent decoders prevent bitstream corruption in Stream A from crashing Stream B. |
| **WebRTC PeerConnection** | Stream-Local | One connection / transport per stream | Independent ICE/DTLS/SRTP sessions ensure peer disconnects or network jitters do not propagate. |
| **Decoded Frame Ring Buffer** | Stream-Local | Bounded `deque(maxlen=K)` with drop-oldest | Strict memory bound per stream ($K \times W \times H \times 3$ bytes). Fast streams never starve or overflow slow streams. |
| **Audio PCM Buffer** | Stream-Local | Bounded duration ring buffer | Independent sample rates, channel layouts, and drift compensation. |
| **AIScheduler State** | Stream-Local | Per-stream adaptive pacing + scene diff EMA | Each stream independently tracks its scene dynamism (e.g. static camera @ 2 FPS vs active action @ 30 FPS). |
| **TemporalFusion State** | Stream-Local | Per-stream timestamp window index | Audio-video skew and window alignment must be evaluated relative to each stream's wall-clock and RTP timeline. |
| **VLM Model Weights** | Process-Global | Single shared GPU-resident instance | Model weights (e.g., 2GB-8GB VRAM) cannot be duplicated $N$ times without instantly exhausting GPU VRAM. |
| **VAD / ASR Models** | Process-Global / Shared | Shared inference worker / adapter | Audio transcription can be dispatched concurrently or sequentially across active speech segments. |
| **GPU Memory Budget** | Process-Global | Dynamic tracking via CUDA telemetry | Global safety check blocks or throttles new stream creation if available VRAM drops below headroom threshold. |
| **Metrics Collector** | Hierarchical | Per-stream metrics rolled into global snapshot | Granular per-stream observability with aggregated throughput, drop, error, and memory counters. |
| **Worker Threads** | Stream-Local + Shared | Dedicated I/O workers, shared/fair inference | Decouples network I/O from compute-intensive neural execution. |

## 3. Core Multi-Stream Components

### 3.1 Stream Identity (`stream_id`)
Every media session in Velo V2.0 possesses a unique string identifier (`stream_id`).
- When creating a stream or session, `stream_id` is supplied (or auto-generated, e.g. `session-0`, `session-1`).
- All log events, metrics, candidate frames, and fusion contexts carry `stream_id`.

### 3.2 StreamSession
Encapsulates all isolated resources for a single active stream:
```python
class StreamSession:
    stream_id: str
    stream: Stream | RtpReceiver
    scheduler: AIScheduler
    audio_scheduler: Optional[AudioScheduler]
    fusion: Optional[TemporalFusion]
    metrics: StreamMetrics
    state: SessionState
```

### 3.3 MultiStreamPipeline Coordinator
`MultiStreamPipeline` provides the unified high-level orchestration for $N$ streams:
- **`add_stream(stream_id, stream, ...)`**: Dynamically attach a new stream session without restarting existing streams.
- **`remove_stream(stream_id)`**: Gracefully close and detach a stream session.
- **`__aiter__() / run()`**: Asynchronously yields `(stream_id, VLMResponse)` or `MultiStreamResult` events as inference completes across streams.
- **Fair Scheduling**: Coordinates candidate dispatch across active streams. If Stream A produces 30 FPS and Stream B produces 15 FPS, candidates are processed with fair round-robin or deficit-weighted scheduling so high-framerate streams do not starve low-framerate streams.

### 3.4 Fault Domain Isolation
A failure in one stream must **never** bring down the runtime or other streams:
1. **Decoder Error in Stream A**: Stream A marks its state as `FAILED` or logs decode drop, stops its local ingestion, while Stream B, C, D continue processing unaffected.
2. **ASR / VAD Exception in Stream A**: Error is caught, metrics recorded for `Stream A`, local audio dropped, remaining pipeline unaffected.
3. **Session Closure**: Calling `remove_stream("stream-1")` closes Stream 1's native decoder and threads without blocking or interrupting Stream 2.

### 3.5 Hierarchical Observability
`RuntimeMetrics` is extended to support hierarchical queries:
- `metrics.stream("stream-1")`: Returns per-stream video drops, queue depth, effective FPS, audio latency, and fusion skew.
- `metrics.global()`: Returns aggregated active stream count, total video throughput, total audio chunks, total inference count, total worker errors, and process GPU memory.

## 4. GPU Resource & Memory Budget Model

For $N$ concurrent streams with resolution $(W, H)$ at target queue depth $K$:
- **Per-Stream NVDEC VRAM**: $\approx K \times W \times H \times 1.5 \text{ bytes (NV12)} + \text{NVDEC surface pool} \approx 30\text{--}60\text{ MB per 1080p stream}$.
- **Shared Model VRAM**: Constant $M_{\text{vlm}}$ (e.g., 2.5 GB for SmolVLM-500M or 0 MB for Mock).
- **Total Process GPU Memory**:
  $$M_{\text{total}} = M_{\text{vlm}} + \sum_{i=1}^N M_{\text{decoder}}^{(i)} + M_{\text{torch\_overhead}}$$

Before accepting a new stream, `MultiStreamPipeline` checks:
$$\text{Available VRAM} \ge M_{\text{stream\_budget}} + M_{\text{safety\_headroom}}$$
Preventing out-of-memory (CUDA OOM) aborts.
