# Velo V1.11: Benchmark Methodology & Performance Taxonomy

## 1. Executive Summary & Measurement Integrity

Velo is a lightweight GPU-native realtime media runtime designed for multimodal AI applications. To ensure absolute transparency and engineering trustworthiness, Velo strictly categorizes and reports all performance figures according to their exact level of hardware, media, and model realism.

> [!IMPORTANT]
> **Velo Benchmarking Creed:**
> 1. **Synthetic Throughput != Hardware Decode Throughput**: Synthetic frame copying in Python/memory (e.g., 120k+ FPS) measures queue throughput and memory bandwidth, NOT NVDEC ASIC decoding performance.
> 2. **Mock-Model Latency != Real VLM Latency**: Synthetic adapter execution (e.g., 10ms) measures runtime pipeline orchestration overhead, not actual Vision-Language Model autoregressive decoding.
> 3. **No Cherry-Picked Runs**: All official benchmark numbers must be reported across multiple runs (Run 1, Run 2, Run 3) with Arithmetic Mean ($\mu$) and Standard Deviation ($\sigma$).
> 4. **Isolate Warmup**: CUDA initialization, decoder initialization, and JIT compilation overhead must be isolated from steady-state throughput.

## 2. Measurement Taxonomy

Every measurement produced by Velo's test and benchmark suites is assigned one of six taxonomy classes:

| Taxonomy Class | Description | Example Metric |
|---|---|---|
| **Class 1: Synthetic Infrastructure** | Pure Python memory queues, ring buffers, and mock time steps. No media decoding or model execution. | `scheduler_benchmark.py` submit rate (40k+ ops/s) |
| **Class 2: CPU-Only Operations** | Real audio calculations (RMS energy, PCM slicing) running purely on CPU cores. | `VAD.analyze()` latency, `AudioScheduler` chunking |
| **Class 3: GPU-Backed Synthetic** | GPU tensors allocated directly on CUDA without video hardware decoding. | PyTorch tensor allocation benchmarks |
| **Class 4: Real Media & Hardware NVDEC** | Genuine Annex-B H.264 NAL packets pushed through RTP into NVIDIA NVDEC ASIC via native C++/Rust bindings. | Real 720p/1080p/4K NVDEC decode FPS and frame intervals |
| **Class 5: Real WebRTC / LiveKit** | Real live WebRTC peer connection transporting video (H.264) and audio (Opus) over RTP/UDP. | LiveKit E2E ingestion and jitter metrics |
| **Class 6: Model Inference (Mock vs Real)** | Execution of downstream AI reasoning. Explicitly divided into: <br>• **6A (Mock VLM)**: Pipeline infrastructure latency <br>• **6B (Real VLM)**: Real weights on CUDA | `MockMultimodalAdapter` (10ms) vs `SmolVLMAdapter` (Real Hugging Face) |

## 3. Real Video Decoding Path (NVDEC)

The genuine hardware decoding pipeline in Velo operates as follows:

```text
Annex-B H.264 Bitstream (SPS, PPS, IDR, Slices)
       │
       ▼ (push_rtp / WebRTC RTP depacketizer)
Native Rust Stream / RtpReceiver
       │
       ▼ (Direct C-API pointer transfer)
NVDEC C++ Hardware Video Decoder
       │
       ▼ (Zero-copy NV12 -> RGB on GPU)
GPU Surface Memory (CUDA Device Pointer)
       │
       ▼ (PyO3 DLPack Capsule)
Velo Frame (GPU-Resident)
       │
       ▼ (torch.from_dlpack: < 5 microseconds)
PyTorch CUDA Tensor (cuda:0, torch.uint8)
```

### Metrics Measured:
- **Max Decode Throughput (FPS)**: Unthrottled NVDEC hardware decoding limit.
- **Sustained Realtime 30 FPS Pacing**: Frame interval consistency (Mean, p50, p95, p99, Jitter).
- **DLPack Zero-Copy Tensor Wrapping Overhead ($\mu\text{s}$)**: Latency of converting `Frame` to `torch.Tensor` on CUDA.
- **GPU VRAM Utilization (MB)**: Allocated and reserved memory before, during, and after streaming.
- **CPU Overhead (%)**: CPU core utilization during sustained hardware decoding.

## 4. Real Audio Processing Path

```text
Opus Bitstream (48 kHz / 2-channel)
       │
       ▼
Native Opus Decoder (Rust / C-API)
       │
       ▼
AudioChunk (int16 PCM bytes)
       │
       ▼
AudioScheduler (Bounded ring buffer, 200ms/500ms consolidation)
       │
       ▼
VAD (RMS energy heuristic)
       │
       ▼
ASRAdapter (Whisper / MockASRAdapter) -> Transcript
```

### Metrics Measured:
- **Chunk Submission Throughput**: Rate of consolidating 20ms raw Opus frames into application slices.
- **VAD Evaluation Latency ($\mu\text{s}$)**: Time to compute RMS energy and determine speech presence.
- **Queue Depth & Backpressure Drops**: Verification of bounded audio history.

## 6. Repeatability & Warmup Methodology

### Warmup Isolation:
To eliminate cold-start distortions:
1. **Warmup Phase**: The first 10-30 frames are decoded to initialize CUDA contexts, NVDEC driver handles, and memory pools. Metrics during this phase are recorded separately as `warmup_latency_ms`.
2. **Steady-State Phase**: All reported throughput, percentiles, and latency distributions are calculated exclusively from the steady-state period.

### 3-Run Statistical Verification:
Every benchmark is executed 3 consecutive times in independent processes. The benchmark summary reports:
- $\text{Run}_1, \text{Run}_2, \text{Run}_3$
- $\text{Mean } \mu = \frac{1}{3}\sum_{i=1}^3 \text{Run}_i$
- $\text{Standard Deviation } \sigma = \sqrt{\frac{1}{3}\sum_{i=1}^3 (\text{Run}_i - \mu)^2}$
