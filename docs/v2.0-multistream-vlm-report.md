# Velo V2.0 Real Multi-Stream VLM Inference Report

## 1. Hardware & Software Environment
- **OS**: Windows 11 (10.0.26200)
- **CPU**: Intel64 Family 6 Model 186 Stepping 2
- **GPU**: NVIDIA GeForce RTX 3050 A Laptop GPU (4.0 GB VRAM)
- **Python**: 3.13.9
- **Torch**: 2.6.0+cu124
- **Transformers Model**: HuggingFaceTB/SmolVLM-Instruct (loaded via `transformers`)

## 2. Benchmark Methodology
The objective was to measure true hardware concurrency when Velo decodes realtime H.264 video streams on the NVDEC engine while simultaneously scheduling inferences on the GPU Tensor Cores using a real Vision-Language Model.

The benchmark `real_multistream_vlm_benchmark.py` was implemented in three phases:
1. **Real VLM Loading Test**: Attempted to instantiate the 2-billion parameter `SmolVLMAdapter` natively in `bfloat16`.
2. **Decoder-Only Baseline**: Measured raw decoding capacity without AI load (established in previous benchmarks at ~1680 FPS for 720p).
3. **Concurrency Analysis**: Used a synchronized `MultiStreamPipeline` to push realtime WebRTC/RTP frames and measure scheduler latency, fairness, and queue limits.

## 3. Real VLM Results (BLOCKED)

## 4. Decoder + Synthetic VLM Concurrency
To test the *runtime orchestration* (independent of the physical model weights), the pipeline was subjected to concurrent synthetic loads using `MockMultimodalAdapter`.
- **Fairness & Scheduling**: The `AIScheduler` successfully orchestrated 1, 2, 4, and 8 concurrent streams without deadlocks.
- **Backpressure**: Frame ingestion correctly drops excessive frames (via `CandidateSelector`) when inference latency climbs, ensuring bounded memory footprint.

## 5. Failure Isolation
A critical milestone requirement was ensuring that if the VLM crashes during inference for *one* stream (e.g., due to tensor dimension mismatch or corrupted visual data), it does not tear down the entire runtime.

- **Automated Validation**: `test_multistream_inference_failure_isolation` was added to the test suite.
- **Behavior**: When a stream intentionally raises a `RuntimeError("Simulated VLM inference crash")`, the pipeline routes the error back to the originating stream context. The failed stream gracefully stops, yielding its final error via `run_inference`, while all adjacent streams continue processing without interruption.

## 6. Known Bottlenecks & Limitations
- **4GB VRAM Limit**: The absolute limiting factor is VRAM. True VLM performance cannot be measured until deployed on an 8GB+ (ideally 16GB+) NVIDIA GPU.
- **Model Import Constraints**: Zero-copy execution for SmolVLM currently requires copying tensors back to the CPU to satisfy HuggingFace's `Processor` PIL constraints, which will introduce latency once VRAM allows the model to run.

## 7. Recommended Next Steps
1. **Hardware Upgrade**: Migrate the test bench to an RTX 4070 (12GB) or cloud A10G (24GB) to unblock the physical SmolVLM execution.
2. **Custom Preprocessor**: Once hardware is secured, rewrite the HuggingFace image processor to accept native PyTorch GPU tensors (avoiding the CPU roundtrip).
